# 本地开发

当前主应用以 `web/` 前端为主；启用账号服务模式时，AI 请求由浏览器携带 Logto Access Token 调用 Account Service，再由服务端转发到 NewAPI。未配置账号服务时仍可使用浏览器本地渠道。

## 1. 启动前端

```bash
cd web
bun install
bun run dev
```

前端默认访问：

```text
http://localhost:3003
```

如需启用 CQ AI Club 登录，在 Logto 控制台创建单页应用，并新建 `web/.env.local`：

```bash
VITE_LOGTO_APP_ID=你的单页应用AppID
VITE_LOGTO_ENDPOINT=https://auth.cqaiclub.asia
VITE_LOGTO_API_RESOURCE=https://account.cqaiclub.asia
VITE_LOGTO_API_SCOPES=ai:invoke
VITE_ACCOUNT_SERVICE_URL=http://localhost:8787
VITE_NEW_API_URL=https://relay.cqaiclub.asia
```

Logto 应用需要登记登录回调 `http://localhost:3003/callback` 和退出后重定向 `http://localhost:3003/`。`VITE_LOGTO_APP_ID` 留空时隐藏登录入口；浏览器前端不需要也不能配置 App Secret。

同时配置 `VITE_LOGTO_APP_ID`、`VITE_LOGTO_API_RESOURCE` 与 `VITE_ACCOUNT_SERVICE_URL` 后，前端会启用账号服务模式：登录取得的 Access Token 发给 Account Service，由它校验身份、按 Client ID 映射应用并代理 NewAPI。只设置 App ID 时仍然只是登录，不会自动取得 AI 模型或额度。

登录后的账户菜单会显示账号服务返回的剩余额度，并链接到 NewAPI 控制台和钱包充值页。充值回跳由 Account Service 根据 Logto Client ID 和请求 Origin 决定，前端不提交回跳地址；NewAPI 控制台地址由 `VITE_NEW_API_URL` 配置，默认是 `https://relay.cqaiclub.asia`；Logto 登录不代表已经建立了 NewAPI 控制台会话。

GitHub Pages 构建从仓库 Actions Variables 读取 `VITE_LOGTO_APP_ID`、`VITE_LOGTO_API_RESOURCE`、`VITE_LOGTO_API_SCOPES` 和 `VITE_ACCOUNT_SERVICE_URL`。提示词库使用构建产物内的同源快照，并由定时构建每日刷新。当前仓库站点需要在 Logto 登记登录回调 `https://cqai-club.github.io/lingweave/callback` 和退出后重定向 `https://cqai-club.github.io/lingweave/`；Vercel 或其他域名按同样规则登记，并把前端 Origin 加入 Account Service 的 `CORS_ALLOWED_ORIGINS`。

## 2. 配置模型

账号服务模式下登录后直接点击“拉取模型”，模型请求会走 Account Service 的 `/v1/models`；本地回退模式下再填写自己的 `Base URL` 和 `API Key`。WebDAV 仍由浏览器前端直连。

OpenAI 渠道的“文本调用协议”在“API 配置”中按渠道单独选择：上游提供 `/v1/chat/completions` 时选择 Chat Completions，提供 `/v1/responses` 时选择 Responses；账号服务默认使用 Chat Completions。

## 3. 同步提示词库

`bun run dev` 和生产构建会先检查 `web/public/prompt-library/`。快照不存在或超过 24 小时时会从上游生成最新的图文精选索引；刷新失败但已有快照时继续使用上次可用版本，首次准备失败时再尝试当前版本 GitHub Release 资源包。如需主动更新：

```bash
cd web
npm run sync:prompts
```

同步器会解析并记录上游效果图 URL，但不下载、裁切或压缩图片；完成前会检查来源最低数量、效果图覆盖率、重复正文、稳定 ID、来源计数和摘要。可执行 `npm run check:prompts` 单独验证当前索引。`web/public/prompt-library/` 不提交到 Git，版本标签发布时由 GitHub Actions 生成 `prompt-library.tar.gz` 并上传到对应 Release。

如需把 Raw 索引发布到 Cloudinary，在仅本地使用且已被 Git 忽略的 `web/.env.cloudinary.local` 中配置：

```bash
CLOUDINARY_CLOUD_NAME=你的CloudName
CLOUDINARY_API_KEY=你的ApiKey
CLOUDINARY_API_SECRET=你的ApiSecret
CLOUDINARY_FOLDER=lingweave/prompt-library
```

然后执行 `npm run sync:prompts:cloudinary`。脚本只发布包含上游图片 URL 的 `index.json`，不会上传图片；浏览器会从上游按需加载效果图。API Secret 不得使用 `VITE_` 前缀；前端和部署环境只需配置公开索引地址：

```bash
VITE_PROMPT_LIBRARY_URL=https://res.cloudinary.com/<CloudName>/raw/upload/lingweave/prompt-library/index.json
```

必须使用上述不含 `/v123/` 版本段的稳定 URL；带版本号的地址会固定在旧快照，无法随覆盖发布自动更新。

## 4. 编译并映射文档

`docs/content/docs/` 是文档的唯一内容源。修改后先编译文档项目：

```bash
cd docs
bun install
bun run build
```

再把静态产物映射到主应用：

```bash
cd ../web
npm run sync:docs
```

主应用会通过 `/docs/` 提供完整文档。也可以在 `web/` 直接执行 `npm run map:docs` 完成编译和映射。

## 5. 运行自动化测试

前端单元测试使用 Vitest，默认单次执行全部用例：

```bash
cd web
bun run test
```

开发时持续监听文件变化：

```bash
bun run test:watch
```

GitHub Actions 会在 push 和 pull request 时自动执行单元测试与 TypeScript 检查。

## 常见场景

- 改画布、页面和交互：主要看 `web/`
- 改测试：主要看 `web/tests/`
- 改提示词同步和发布资源下载：主要看 `web/scripts/sync-prompts.mjs`、`web/scripts/ensure-prompts.mjs`
- 改文档站内容：主要看 `docs/content/docs/`，完成后重新编译并映射
