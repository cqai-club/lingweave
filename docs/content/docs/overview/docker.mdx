# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 使用发布镜像

```bash
git clone git@github.com:g-dxw/lingweave.git
cd lingweave
docker compose up -d
```

启动后访问：

```text
http://localhost:3000
```

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

镜像未配置 Logto App ID 时隐藏登录入口。需要在自定义构建中启用登录时：

```bash
VITE_LOGTO_APP_ID=你的单页应用AppID \
VITE_LOGTO_API_RESOURCE=https://account.cqaiclub.asia \
VITE_LOGTO_API_SCOPES=ai:invoke \
VITE_ACCOUNT_SERVICE_URL=https://account.cqaiclub.asia \
VITE_PROMPT_LIBRARY_URL=https://res.cloudinary.com/<CloudName>/raw/upload/lingweave/prompt-library/index.json \
docker compose -f docker-compose.local.yml up -d --build
```

这些变量会写入前端静态产物，修改后需要重新构建镜像。Logto 控制台还需要登记部署域名对应的 `/callback` 和应用根地址；Account Service 还要把部署域名加入 `CORS_ALLOWED_ORIGINS`。不要把 App Secret、NewAPI 管理员 Token 或 `NEW_API_INTERNAL_TOKEN` 写入镜像或前端环境变量。

## 文档站镜像

文档站位于 `docs/` 目录。根目录主应用镜像会先将文档静态编译，再映射到主应用的 `/docs/`，因此默认不需要额外启动文档容器。

如果只需要单独部署文档，也可以使用文档镜像：

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

当前主应用镜像使用 nginx 托管主应用和已编译文档。账号服务模式下浏览器不保存平台 AI API Key；本地回退模式下渠道 Key 仍保存在浏览器本地。画布、我的素材和生成记录默认保存在浏览器本地，提示词库和帮助文档随静态产物发布，不需要额外挂载数据目录。
